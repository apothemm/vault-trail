# VaultTrail

![CI](https://github.com/apothemm/vault-trail/actions/workflows/ci.yml/badge.svg)

C# / .NET 10. Локальное хранилище резервных снимков с дедупликацией по SHA-256. Снимки можно сравнить, проверить и восстановить.

## Возможности

- **Snapshot:** параллельное копирование и хеширование с ограничением 1–16 работников.
- **Deduplication:** одинаковые файлы используют общий объект; снимок публикуется только после успешного копирования всех файлов.
- **List / diff:** каталог снимков, добавленные, удалённые и изменённые файлы.
- **Verify:** проверка размера и хеша каждого объекта снимка.
- **Restore:** предварительный просмотр по умолчанию; запись только с `--apply`, в пустой каталог.
- Символические ссылки пропускаются; пути манифеста проверяются перед восстановлением.
- Блокировка хранилища предотвращает одновременное создание снимков.

## Запуск

```text
dotnet build -c Release
dotnet run -- --store ./vault snapshot ./documents --workers 4
dotnet run -- --store ./vault list
dotnet run -- --store ./vault diff SNAPSHOT_A SNAPSHOT_B
dotnet run -- --store ./vault verify SNAPSHOT_ID
dotnet run -- --store ./vault restore SNAPSHOT_ID ./recovered
dotnet run -- --store ./vault restore SNAPSHOT_ID ./recovered --apply
python -m unittest discover -s tests -v
```

## Проверки

GitHub Actions выполняет сборку и тесты. Тесты находятся в исходниках репозитория и работают на временных данных.

## Ограничения

Это файловые снимки, а не VSS: изменяющиеся файлы могут прервать snapshot, а согласованность базы данных не гарантируется. Права доступа, пустые папки и альтернативные потоки NTFS не сохраняются. Шифрования, сжатия и автоматического удаления старых объектов нет. Прерванное восстановление может оставить часть файлов в каталоге назначения. Не меняйте вручную хранилище и не используйте его одновременно через другой софт. Дедупликация не заменяет резервную копию на отдельном диске.
